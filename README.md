## 2. 과제 목표 자가 점검

미션에서 요구한 "학습자가 스스로 설명할 수 있어야 하는 것" 6가지를 이번 프로젝트 기준으로 정리하면:

1. **HTML/CSS/JS의 역할** — `index.html`(구조) / `css/style.css`(스타일) / `js/app.js`(동작) 로 명확히 분리되어 있음
2. **사용자 입력 → fetch → 화면 반영 흐름** — 퀴즈 답변 선택 → `state.answers`에 저장 → 채점 후 `/api/analyze`, `/api/ask`로 `fetch` 요청 → 응답을 결과 화면에 렌더링
3. **Vercel Serverless Functions 구조** — `api/analyze.py`, `api/ask.py`가 각각 `/api/analyze`, `/api/ask` 경로로 자동 매핑됨 (폴더 경로 = URL 경로)
4. **환경 변수로 API 키 관리하는 이유** — `GEMINI_API_KEY`, `GROQ_API_KEY`를 코드에 하드코딩하지 않고 Vercel Environment Variables로 분리 (README 6번 참고)
5. **로컬 vs 배포 환경 차이** — 정적 파일만 열면 `/api`가 동작하지 않음(서버 부재), `vercel dev` 또는 실제 배포에서만 AI 기능 확인 가능함을 실습으로 확인
6. **AI 생성 코드의 오류 원인 파악·수정** — 아래 5장 "진행 이력"에 실제로 겪은 오류와 원인 분석·수정 과정을 기록

## 5. 진행 이력 — 초기 구축 이후 추가로 진행한 작업

미션 요구사항을 충족하는 최초 버전을 만든 이후, 실제 배포·테스트 과정에서 발생한 문제들을 해결하고 기능을 보강했습니다. 이 과정 자체가 미션의 과제 목표 6번("AI 생성 코드의 오류 원인을 파악하고 수정 방향을 설명할 수 있다")에 해당하는 실습 기록입니다.

### 5-1. 배포 환경 설정
- Vercel 프로젝트 생성, GitHub 연동, Environment Variables(`GEMINI_API_KEY`) 등록 및 Deploy 진행

### 5-2. 저장소 구조 문제 해결
- **증상**: 배포 후 CSS가 전혀 적용되지 않음
- **원인 파악**: 저장소 최상위에 프로젝트 폴더(`tone-project/`)가 한 단계 더 들어가 있어, Vercel이 참조하는 루트 경로에 예전 버전의 중복 파일이 남아있었음
- **수정**: 하위 폴더 안의 모든 파일을 저장소 최상위로 이동, 중복 파일(`index.html`, `README.md` 등) 및 불필요한 `.zip` 파일 정리 후 재커밋

### 5-3. API 라우팅 문제 해결
- **증상**: `/api/analyze` 요청이 404 반환
- **원인 파악**: `analyze.py`가 `api/` 폴더 없이 저장소 최상위에 바로 위치 — Vercel은 폴더 경로를 그대로 라우팅 경로로 사용하므로 `api/` 폴더가 없으면 해당 엔드포인트가 존재하지 않음
- **수정**: `api/analyze.py` 경로로 정확히 재배치

### 5-4. AI 모델 지원 종료 대응
- **증상**: 구조 수정 후에도 AI 호출 실패
- **원인 파악**: 코드에 명시된 `gemini-2.0-flash` 모델의 API 지원이 종료된 상태였음
- **수정**: 현재 사용 가능한 `gemini-2.5-flash`로 모델명 변경

### 5-5. AI 응답 잘림(truncation) 문제 해결
- **증상**: AI 코멘트가 "와, 당신은 역시" 등 한두 어절에서 끊김
- **원인 파악**: `gemini-2.5-flash`가 답변 생성 전 내부적으로 소비하는 사고(thinking) 토큰이 `maxOutputTokens` 한도 안에 포함되는데, 한도(200)가 지나치게 낮게 설정되어 있었음
- **수정**: `thinkingConfig.thinkingBudget: 0`으로 설정해 사고 단계를 생략하고, `maxOutputTokens`을 상향 조정

### 5-6. 기능 보강 — AI 코멘트 상세화
- 기존 2~3문장짜리 단문 코멘트를, **오늘의 한마디 / 답변에서 보이는 특징 / 강점이 빛나는 순간 / 오늘을 위한 조언** 4단락 구조로 확장
- 프론트엔드에서 소제목이 있는 카드 형태로 렌더링되도록 UI 개선

### 5-7. 신규 AI 기능 추가 — "AI에게 더 물어보기"
- 결과 화면에 자유 질문 입력창을 추가하고, `api/ask.py`를 신규 구현
- 사용자가 자신의 유형에 대해 궁금한 점을 직접 물어보면 유형 맥락을 반영한 답변을 받는 대화형 기능으로, 요구사항 최소 기준(AI 기능 1개)을 넘어 2개로 확장

### 5-8. API 할당량 소진 대비 — Groq 백업(fallback) 구성
- **배경**: Gemini 무료 티어의 하루 요청 한도가 낮아, 데모/평가 시 소진될 가능성을 우려
- **대응**: `api/analyze.py`, `api/ask.py` 각각에 `call_gemini()` / `call_groq()` 함수를 분리 구현하고, Gemini 호출이 실패하면 자동으로 Groq(`llama-3.3-70b-versatile`)으로 재시도하는 `generate_comment()` / `generate_answer()` 로직 추가
- **결과**: Gemini → Groq → (모두 실패 시) 정적 설명, 3단계 안전망 구조 완성. `GROQ_API_KEY`는 선택 항목으로, 없어도 기존 동작에는 영향 없음

### 5-9. 문서 최신화
- `README.md`에 AI 기능 2종, provider 이중화 구조, 트러블슈팅 기록표를 반영해 재작성
- `PLANNING.md`에 AI 기능 ①/② 구분, provider 이중화 섹션, 보너스 아이디어 항목 추가
